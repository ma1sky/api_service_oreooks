# API Service (ОреОКС бэкенд)

## 1. Название и назначение сервиса
API Service (backend) для бота Telegram "ОреОКС". Предоставляет REST API для управления задачами, расписанием и событиями пользователей, интегрируется с внешним сервисом ORIOKS для получения данных об учебном процессе.

Основные функции:
- Аутентификация пользователей через токен ORIOKS.
- Управление персональными задачами (создание, чтение, обновление, удаление).
- Получение расписания занятий на конкретную дату.
- Получение контрольных мероприятий (событий) на конкретную дату.

## 2. Архитектура и зависимости
- **Технологии и фреймворки:** Node.js, Express, TypeScript, PostgreSQL (через Prisma ORM), Zod для валидации данных.
- **Взаимодействие с другими микросервисами:** 
  - Обменивается данными с бот-сервисом (Telegram бот) через HTTP-запросы.
  - Взаимодействует с внешним API ORIOKS (orioks.miet.ru) для получения актуального расписания и событий.
- **Используемые внешние сервисы:** 
  - PostgreSQL – основное хранилище данных.
  - Redis – используется бот-сервисом для хранения сессий (в данном сервисе не используется напрямую).
  - ORIOKS API – внешний источник учебных данных.

## 3. Способы запуска сервиса

### Локальный запуск через Docker
```bash
docker build -t api_service .
docker run -p 3000:3000 api_service
```

### Альтернативный запуск без Docker
1. Установите зависимости:
   ```bash
   npm install
   ```
2. Создайте файл `.env` на основе `.env.example` и заполните переменные окружения:
   ```env
   DATABASE_URL=postgresql://user:password@localhost:5432/dbname
   PORT=3000
   ORIOKS_BASE_URL=https://orioks.miet.ru
   ```
3. Примените миграции базы данных:
   ```bash
   npx prisma migrate deploy
   ```
4. Соберите проект:
   ```bash
   npm run build
   ```
5. Запустите сервер:
   ```bash
   npm start
   ```

### Переменные окружения
- `DATABASE_URL` – строка подключения к PostgreSQL (обязательно)
- `PORT` – порт, на котором будет работать сервер (по умолчанию 3000)
- `ORIOKS_BASE_URL` – базовый URL API ORIOKS (по умолчанию https://orioks.miet.ru)

## 4. API документация
OpenAPI/swagger документация отсутствует. Основные эндпоинты:

| Метод | Путь | Описание |
|-------|------|----------|
| POST | `/auth` | Аутентификация пользователя по токену ORIOKS |
| GET | `/users/:tgId/schedule/:date` | Получить расписание на указанную дату (дата в формате YYYY-MM-DD) |
| GET | `/users/:tgId/events/:date` | Получить события на указанную дату |
| GET | `/users/:tgId/tasks` | Получить все задачи пользователя |
| POST | `/users/:tgId/tasks` | Создать новую задачу |
| PUT | `/users/:tgId/tasks/:id` | Обновить существующую задачу |
| DELETE | `/users/:tgId/tasks/:id` | Удалить задачу |

**Формат ответа:** все ответы обёрнуты в объект с полем `success` (boolean) и дополнительными данными. В случае ошибки может присутствовать поле `reason` с пояснением.

Пример успешного ответа:
```json
{
  "success": true,
  "schedule": { ... }
}
```

Пример ошибки:
```json
{
  "success": false,
  "reason": "Пользователь не найден"
}
```

## 5. Как тестировать
- Запуск unit-тестов: `npm test`
- Запуск тестов с покрытием кода: `npm run test:coverage`
- Запуск тестов в watch-режиме (автоматический перезапуск при изменениях): `npm run test:watch`

Тесты расположены в директории `src/**/__tests__/` и используют Jest в качестве тестового фреймворка.
